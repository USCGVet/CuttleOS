    Drive the appliance

    Every operation goes through the Triad controller, never to one VM directly. That's what keeps the three hearts consistent.

    1 · CONNECTPaste the operator token from the controller's terminal.
    2 · LOOKReads and inspections are safe: they run on every online node and you see all three answers.

    Kernel role:

    🗄️

    SQLone database, three copies

    read · 2-of-3 votewrite · WAL + parity

    Reads run on every online node, and the controller returns the answer the majority agrees on. A write gets the next transaction number, lands in the write-ahead log, runs on every online node, and refreshes the XOR parity block. A node that's mid-morph replays it from the log when it wakes.

    you→controller→OS-1 · OS-2 · OS-3→majority / WAL→you
    🔎

    Inspectread-only shell on each node

    read-only

    Runs an inspection command on every online node and puts the three answers side by side. Each node has its own keys and kernel binary, so some answers are supposed to differ. The controller refuses state-changing commands here; those have to go through SQL or the apps below.

    🔐

    Vaultsealed secrets

    get · 2-of-3 voteput/del · encrypted WAL

    Each node seals the value under its own hardware-derived key. The log stores puts encrypted, so a node that missed one re-seals it while it catches up.

    Guard & Cronposture and scheduled jobs

    🧬

    Moving-target defenserotate the kernel binaries

    one node at a time

    A morph drains a node and seals its disk, rewrites its kernel with binmorph under a fresh seed, and reboots it. Then it replays any writes it missed. Only one node morphs at a time, so two hearts always hold the majority. The Live Cycle tab shows each stage.

    🎯

    Guided drillsprove the guarantees, step by step

    Zero-downtime write

    Morphs one node, writes a row while it's away (only 2/3 get it), waits for the node to rejoin, then checks it replayed the write from the WAL.

      Tamper & self-heal

      Plants a rogue row on one node only. The 2-of-3 vote outvotes it, the controller rebuilds it from the majority plus the WAL, and it gets an emergency re-morph.

        Response inspector

        Run an operation and the controller's verdict appears here, with each node's own answer side by side. Agreeing answers are green, outvoted ones red, queued ones amber.
